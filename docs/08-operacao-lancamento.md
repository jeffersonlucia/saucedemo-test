# 08 - Operacao e lancamento

## Estrategia de lancamento

Lancar primeiro com clubes piloto selecionados, aprendendo com operacao real antes de escalar para varios clientes.

## Cliente piloto ideal

- Tem base de membros ativa.
- Faz eventos/degustacoes recorrentes.
- Usa processos manuais hoje.
- Dono ou gerente acessivel para feedback.
- Aceita operar com produto em evolucao.
- Tem necessidade clara de unidade, agenda e membros.

## Onboarding de clube

### Checklist comercial

- Confirmar plano contratado.
- Definir responsavel do clube.
- Mapear unidades.
- Mapear planos de membros existentes.
- Mapear eventos recorrentes.
- Definir identidade visual.
- Definir canal de suporte.

### Checklist tecnico

- Criar tenant.
- Criar unidades.
- Configurar branding.
- Importar membros.
- Criar planos.
- Criar usuarios da equipe.
- Criar eventos iniciais.
- Validar flavor/config no app.
- Rodar smoke test.

### Checklist de treinamento

- Como acessar.
- Como cadastrar membro.
- Como criar evento.
- Como reservar pelo membro.
- Como fazer check-in.
- Como registrar estoque.
- Como abrir suporte.

## Materiais de venda

- One-pager do produto.
- Demo com tenant ficticio.
- Video curto do fluxo dono/cliente final.
- Calculadora simples de ROI: membros ativos, eventos, no-show e receita.
- FAQ de seguranca e LGPD.
- Comparativo: planilha/WhatsApp vs plataforma.

## Modelo comercial inicial

Opcoes a validar:

1. Mensalidade por clube.
2. Mensalidade por unidade.
3. Mensalidade + faixa de membros ativos.
4. Add-ons: app white-label publicado, billing integrado, analytics avancado.
5. Setup fee para implantacao e importacao.

## Suporte

### Niveis

- N1: duvidas de uso, acesso, cadastros.
- N2: problemas operacionais, dados, configuracoes.
- N3: bugs tecnicos, incidentes, performance.

### Canais

- Email de suporte.
- WhatsApp/Slack para piloto.
- Base de conhecimento.
- Status page em fase posterior.

## Documentacao de usuario

Guias necessarios:

- Primeiro acesso.
- Configuracao do clube.
- Cadastro de membros.
- Criacao de planos.
- Criacao de eventos.
- Reserva pelo membro.
- Check-in de evento.
- Controle de estoque.
- Como interpretar dashboard.
- Perguntas frequentes.

## Indicadores do piloto

| Indicador | Leitura |
| --- | --- |
| Ativacao do clube | Conseguiu configurar unidade, membros e eventos |
| Ativacao do membro | Membros acessaram e reservaram |
| No-show | Reducao ou melhor visibilidade de ausencias |
| Uso admin | Frequencia de gerente/dono no painel |
| Erros por usuario | Qualidade tecnica |
| Chamados por fluxo | Onde produto esta confuso |
| Tempo de check-in | Eficiencia operacional |

## Plano de feedback

### Dono do clube

Perguntas:

- O dashboard ajuda a tomar decisao?
- O sistema reduz trabalho manual?
- A experiencia parece premium para sua marca?
- O que impediria voce de pagar mensalmente?
- Qual relatorio falta?

### Gerente/staff

Perguntas:

- Criar evento foi simples?
- Check-in funcionou no ritmo da operacao?
- Cadastro de membro atende a rotina?
- Estoque precisa ser mais detalhado?

### Cliente final

Perguntas:

- Voce entendeu seus beneficios?
- Reservar evento foi facil?
- A comunicacao foi clara?
- O app parece do clube que voce frequenta?

## Release readiness checklist

- Todos os fluxos P0 testados.
- Dados de tenant isolados.
- Backups configurados.
- Logs e Sentry ativos.
- Runbook de incidente pronto.
- Guia de usuario pronto.
- Responsaveis de suporte definidos.
- Termos e privacidade revisados.
- Smoke test do tenant piloto aprovado.

## Pos-lancamento

Rotina sugerida:

- Revisar metricas semanalmente durante piloto.
- Consolidar feedback por modulo.
- Classificar bugs por severidade.
- Atualizar backlog.
- Priorizar melhorias que reduzem operacao manual ou aumentam receita.

## Decisoes pendentes antes de vender em escala

- Modelo de precificacao final.
- Politica de app white-label por loja.
- SLA comercial.
- Contrato e termos legais.
- Processo de importacao de dados.
- Processo de suporte e treinamento.
- Limites de uso por plano.
